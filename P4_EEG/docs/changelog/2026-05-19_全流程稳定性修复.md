# P4 全流程稳定性修复报告 (2026-05-19)

关联：[[proposal]] · [[paper_blueprint]] · [[P4_实验操作指南]] · [[P4_真实设备连接与正式采集指南]] · [[P4_Trigger打标联调复盘]] · [[experiment/README|experiment/README]]

> [!important] 结论先行
> - 本次修复彻底解决了 `python launcher.py --session all` 模式下 **Session 3 SSVEP 阶段 EEG 软件收不到 Marker** 的问题；同时解决了 Session 4 的同类隐患。
> - SSVEP 闪烁速率漂移（"四方块都闪得很快/慢"）改成了按帧严格计数 + warm-up + 刷新率自检，根除时钟驱动循环的时序漂移。

> - 顺手补齐了 Session 1 / 重基线 / 过渡期的 ESC 即时退出能力，主试随时可以中止。
> - S2 摇头/点头 (46/47/48) 写入了 `MARKER_TABLE`；所有项目文档的旧 Marker 编码 (100/200/131-134/1100/1200/151-154 等) 全部对齐到当前 8-bit 编码。

## 1. 用户在 2026-05-18 报告的问题

1. 全流程模式 (`--session all`) 下，跑到 S3 的 SSVEP 部分时，**EEG 软件里完全看不到 Marker**；但单独跑 S3 没问题。

## 2. 根因诊断

### 2.1 Bug A — `launchall` 模式 S3 SSVEP 无 Marker

代码路径：[[experiment/launcher.py]] 中 Session 3 的子流程是 `run_oddball` → 1 分钟重基线 → `run_ssvep`。

漏洞链：

1. `run_oddball(cfg)` 末尾会 `cleanup_all()`，关闭 oddball 自己创建的串口和窗口。
2. 紧接着「1 分钟重基线」段落 `trigger = TriggerSender(...)` 重新打开 COM3 用于发送基线 Marker。
3. 重基线段结束时**只调用了 `win.close()`，没有 `trigger.close()`**——那个 `trigger` 实例仍然持有 COM3。
4. 立刻进入 `run_ssvep(cfg)`，内部新建另一个 `TriggerSender` 想再次打开 COM3 → `serial.Serial(...)` 抛 `PermissionError: Access is denied`。
5. 异常被 `__init__` 捕获后**静默降级到 `no_hardware=True`**——SSVEP 阶段一个 Marker 都不发，但日志里看不到明显错误。

> [!note] 为什么单跑 S3 不复现
> `cleanup_all` 注册在 `atexit`。单跑 S3 时进程在 SSVEP 结束后退出，atexit 触发清理串口；连跑时进程不退出，atexit 不会触发，旧 trigger 一直占着 COM3。

### 2.2 Bug B — S4 Oddball → SSVEP 的串口竞争

S4 在 `launcher.py` 中没有重基线段，但 `run_oddball` 末尾 `cleanup_all()` 关闭 COM3 后，**Windows 串口驱动有大约 100–300 ms 的释放延迟**。`run_ssvep` 立刻新建 `TriggerSender` 时也可能撞上 "Access denied"，同样静默降级到 no_hardware。

### 2.3 Bug C — SSVEP 闪烁速率漂移

代码路径：[[experiment/session3_ssvep.py]] 的主闪烁循环。

漏洞链：

1. 原循环用 wall-clock 控时：`while core.getTime() - flicker_start < FLICKER_DURATION`。
2. 内部 counters 是按渲染循环计数。如果任意一帧 vsync 失同步、Windows 抢占、GPU 卡顿，导致单次循环耗时 >16.67 ms，那么外层 wall clock 仍按 1 倍速走，但 counters 只加 1 次 → **4 秒内画的帧数不一样 → 实际频率漂移**。
3. `win.getActualFrameRate()` 测量噪声大，在 Windows 动态刷新率 / VRR / Game Mode 启用时可能返回 90 Hz / 120 Hz 之类的杂乱值。
4. 进入 `_compute_runtime_specs(actual_fps)` 后，`int(round(fps/hz))` 会因为微小 fps 波动反复跳变，每个 trial 的 frames_per_cycle 不稳定 → 整体闪烁节奏看起来"忽快忽慢"。
5. launcher 在 session 切换时反复 close / new window，可能触发显卡刷新率切换。

### 2.4 Bug D — Session 2 水平眼动小球太小太短

[[experiment/session2_artifacts.py]] 原代码：

- `ACTION_DURATION = 1.0` 秒（被所有伪迹类型共用）
- 小球从 ±0.25 到 ∓0.25（PsychoPy `height` 单位，移动总长 ≈ 540 px）
- 半径 0.02（PsychoPy `height` 单位）

视觉上确实又快又短，被试还没反应过来就结束了。

### 2.5 其他隐患（主动排查）

- **S2 摇头/点头 marker 46 / 47 / 48** 在代码里被写成裸数字直接发，但 `MARKER_TABLE` 里没登记；与 Marker 命名一致性约定不符。
- **`_generate_trial_sequence` 是 `while True` 无限循环**，理论上存在极端比例下死循环风险。
- **`run_full_experiment` 5 秒倒计时**只用 `time.sleep(1)`，没有任何中止入口，Ctrl+C 会被吃掉。
- **Session 1 两个 2 分钟静息 + 30 秒过渡 + S3 重基线 1 分钟**全部用 wall-clock 循环 `win.flip()`，期间 **ESC 完全无效**。主试发现被试嗜睡或不适时只能 Ctrl+C 强杀。
- **proposal / paper_blueprint / 两份操作指南 / experiment README** 里的 Marker 编号仍写旧值（100/200/1100/1200/131-134/151-154），与 `config.py:MARKER_TABLE` 不一致。

## 3. 修复清单

### 3.1 代码层修复（共 4 个文件）

| 文件 | 修复内容 |
| --- | --- |
| `experiment/launcher.py` | (a) S3 重基线段裹 `try / finally`，结束时**显式** `trigger.close()` + `win.close()` + `core.wait(0.5)`，杜绝 Bug A 的串口占用泄漏。 (b) S4 SSVEP 启动前插入 `core.wait(0.5)`，给 Windows 串口驱动释放时间，缓解 Bug B。 (c) S3 重基线 60s while 循环加 ESC 即时退出。 (d) `run_full_experiment` 的 5 秒倒计时支持 `KeyboardInterrupt`，主试可在过渡期 Ctrl+C 中止全流程。 |
| `experiment/utils.py` | (a) `TriggerSender.__init__` 加 5 次重试（每次间隔 0.3 s），任何串口短暂占用都会被吃掉，不再静默降级到 no_hardware。 (b) `TriggerSender.close()` 加去重保护，清掉全局引用，避免 `cleanup_all` 重复关闭报错。 (c) `cleanup_all` 关闭串口后强制 sleep 0.3 s 给驱动释放时间。 |
| `experiment/session3_ssvep.py` | (a) `_get_refresh_rate` 改为连测两次取最接近 60 Hz 的一次，容忍范围内强制吸附到 60 Hz（避免 59.7 → frames_per_cycle 在 6 / 7 / 10 之间跳变）；偏离 >1.5 Hz 弹警告告诉用户去 Windows 设置里固定刷新率。 (b) **主闪烁循环改成按帧计数** `for _frame_i in range(total_flicker_frames)`，不再依赖 wall clock，counters 与 vsync 严格绑定 → 各频率独立、不会被 GPU 卡顿错速。 (c) 首个 trial 前 warm-up 60 帧丢弃，让 vsync 进入稳态。 (d) 开启 `recordFrameIntervals` + `refreshThreshold`，每个 trial 的丢帧数 + 总丢帧数 + 全部 `frame_intervals_s` 写入 `session_data`，后处理时可剔除丢帧 trial。 |
| `experiment/session2_artifacts.py` | (a) 水平眼动单独参数化：`SACCADE_DURATION = 2.0`（原 1.0），`SACCADE_BALL_AMPLITUDE = 0.42`（原 ±0.25），`SACCADE_BALL_RADIUS = 0.028`（原 0.02），运动距离 ≈ 全屏 84% 宽度。 (b) 所有裸数字 Marker 改为 `MARKER_TABLE["..."]` 引用，新增 `SACCADE_MARKER` 常量；`art_marker == 43` 全部替换为 `art_marker == SACCADE_MARKER`。 (c) "是不是最后一类伪迹"的判断从用 marker 比较改为用 `art_idx`，逻辑更稳。 (d) `session_data` 加 `saccade_action_duration_s / saccade_ball_amplitude_height_units / saccade_ball_radius_height_units` 记录。 |
| `experiment/session1_resting.py` | 睁眼 2 分钟 + 闭眼 2 分钟 + 30 秒过渡期全部改成支持 ESC 即时退出。 |
| `experiment/session3_oddball.py` | `_generate_trial_sequence` 加 `max_retries=1000`，超出抛 `RuntimeError`，杜绝理论死循环。 |
| `experiment/config.py` | `MARKER_TABLE` 新增 `S2_HEAD_LEFT=46 / S2_HEAD_RIGHT=47 / S2_HEAD_NOD=48`，与 Session 2 实际发送 marker 一一对应。 |

> [!success] 双保险设计
> Bug A 和 Bug B 现在被两层机制保护：
> 1. `launcher.py` 在 session/段落切换处显式释放 + sleep；

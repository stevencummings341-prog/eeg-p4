# P4 Trigger 打标联调复盘

关联笔记：[[proposal]] · [[P4_实验操作指南]] · [[P4_真实设备连接与正式采集指南]]

> [!warning] 结论先行
> 这次 iRecorder 的 Trigger 正确配置是：
> - **端口：COM3**
> - **波特率：115200**
> - **协议帧：`marker, 0x55, 0x66, 0x0D`**
> - 串口调试助手发送 `01 55 66 0D` 时，EEG 软件显示 **`T1`**。

## 1. 这次到底错在哪里

### 1.1 最初 Python 的 Trigger 协议错了

最初 Python 代码只发送了单字节 marker：

```text
marker
0
```

但可工作的 MATLAB 脚本 `experiment/task3_v4.m` 实际发送的是 4 字节帧：

```text
marker, 0x55, 0x66, 0x0D
```

所以 Python 虽然能打开串口，但 EEG 软件始终看不到事件。

### 1.2 后来又被“9600”带偏了

中间根据设备管理器里 COM3 属性显示的 `9600`，把 Python 默认波特率改成了 9600。

但这一步后来证明是错的，因为：

- MATLAB 可工作的参考脚本里实际写的是 **115200**；
- 串口调试助手用 **115200** 发送 `01 55 66 0D` 时，EEG 软件能显示 **`T1`**；
- 串口调试助手用 **9600** 时，没有 marker。

> [!note]
> 设备管理器里显示的串口“默认属性”不等于当前实验真实生效的通信波特率。真实波特率要以**可工作的参考脚本**或**串口调试助手实测**为准。

### 1.3 太晚才做最小测试

真正破局的动作不是继续猜协议，也不是继续改 PsychoPy，而是：

1. 关闭 MATLAB / Python 等占用串口的程序；
2. 用串口调试助手直接发字节；
3. 在 EEG 软件里观察有没有 marker；
4. 用最小方式确认：
   - COM 口对不对；
   - 波特率对不对；
   - 协议对不对。

这一步应该更早做。

## 2. 最后确认下来的正确配置

### 2.1 正确的串口参数

```text
COM3
115200
8N1
无流控
```

### 2.2 正确的 Trigger 帧协议

发送一个 marker 时：

```text
marker, 0x55, 0x66, 0x0D
```

归零时：

```text
0, 0x55, 0x66, 0x0D
```

### 2.3 串口调试助手的验证证据

串口调试助手设置为：

```text
COM3
115200
HEX 模式
```

发送：

```text
01 55 66 0D
```

EEG 软件显示：

```text
T1
```

这证明：

- 当前 trigger 输入路径是通的；
- iRecorder 能识别这种 4 字节帧；
- Python 只要和这个配置一致，就应该能打标。

---

## 3. Python 代码最终应该怎么做

当前 Python 需要满足两件事：

### 3.1 波特率必须是 115200

默认值应该保持在：

- `experiment/config.py`
- `experiment/utils.py`
- GUI 默认波特率

都用 **115200**。

### 3.2 发送协议必须和 MATLAB 一致

`experiment/utils.py` 中 Trigger 发送逻辑应该是：

```text
发送 marker 帧
等待 5ms
发送归零帧
```

帧格式：

```text
marker, 0x55, 0x66, 0x0D
```

## 4. 这次联调得到的经验教训

### 4.1 不要先相信“听说”的参数

遇到 Trigger 问题，优先级应该是：

1. **可工作的参考脚本**
2. **串口调试助手实测**
3. 设备管理器属性
4. 口头记忆 / 现场印象

### 4.2 先做最小测试，不要先改整套实验脚本

最优顺序：

1. 串口调试助手发最小 marker；
2. EEG 软件确认出现事件；
3. 再让 Python 完全照抄同样的端口、波特率和协议；
4. 最后再跑 Session。

### 4.3 “串口能打开”不等于“EEG 能收到 marker”

这次就出现了这种情况：

```text
串口能打开
PsychoPy 打印“发送成功”
EEG 软件仍然 0 事件
```

所以真正的判据永远是：

> **EEG 软件里有没有看到 marker。**

### 4.4 Trigger 联调要和正式采集分开

Trigger 没联调成功前：

- 不要采正式被试数据；
- 最多做流程演练；
- 所有无 marker 或 marker 不可信的数据都标记为 `PilotTest`，不能直接进数据集。

## 5. 下次开始正式实验前的 Trigger Checklist

> [!todo]
> 每次正式采集前，先过这一遍。

### 5.1 串口与设备

- [ ] EEG 设备是 iRecorder，Trigger 路径已确认
- [ ] Trigger 端口是 **COM3**
- [ ] 波特率是 **115200**
- [ ] 8N1，无流控
- [ ] EEG 软件已经开启事件/marker 显示

### 5.2 串口调试助手验证

- [ ] 关闭 PsychoPy / MATLAB，避免占用 COM3
- [ ] 串口调试助手成功打开 COM3
- [ ] HEX 模式已勾选
- [ ] 发送 `01 55 66 0D` 后，EEG 软件能显示 `T1`
- [ ] 如需再测，发送 `1E 55 66 0D`，确认是否显示 `T30`

### 5.3 Python 启动前

- [ ] `launcher.py` 使用 `--port COM3`
- [ ] Python 默认波特率仍是 **115200**
- [ ] `utils.py` 中 Trigger 帧仍是 `marker, 0x55, 0x66, 0x0D`
- [ ] 终端启动后能看到：`串口 COM3 连接成功 (波特率 115200)`

### 5.4 正式 Session 2 前

- [ ] 先跑 1-2 个 trial 看 EEG 软件里有没有 `T30 / T31 / T41-45`
- [ ] 确认 Marker 进入 EEG 记录后再正式继续

## 6. 还需要继续注意的问题

> [!success] 后续处置 (2026-05-18 更新)
> 这一节描述的 Session 4 marker 截断问题已经在 `experiment/config.py:MARKER_TABLE`
> 中按下面建议的方式解决：S3 / S4 全部 Marker 都重写为 8-bit (< 128) 独立编码，
> 不再使用 "+1000" 偏移方案。详见 [[proposal#Marker 速查总表]] 和
> [[P4_真实设备连接与正式采集指南]]。下面保留原始诊断文字以备追溯。

### 6.1 历史记录：原始 "+1000" 方案的截断风险

> [!bug]
> Session 4 早期设计里使用：
>
> ```text
> 1100 / 1200 / 1126 / 1128 / 1130 / 1140
> ```
>
> 但当前串口协议的 marker 主字节本质上仍是单字节，范围只有 0-255：
>
> ```text
> 1200 → 会被截断
> ```

### 6.2 当前 8-bit 编码 (落地版)

| Session | Oddball 标准/靶 | SSVEP 6 / 8.57 / 10 / 15 Hz | 重基线 |
| --- | --- | --- | --- |
| S3 | 61 / 62 | 71 / 72 / 73 / 74 | 63 |
| S4 | 81 / 82 | 91 / 92 / 93 / 94 | (S4 不重基线) |

S2 伪迹模板：30 (按键) / 31 (动作起始) / 41-48 (8 类伪迹)。
S1 静息态：11 / 12 / 21 / 22。

所有编号均 < 128，iRecorder 单字节 Trigger 协议下可被忠实记录、可在 EEG 软件里直接区分 S3 / S4。

---

## 7. 推荐的以后排查顺序

以后遇到 Trigger 问题，按下面顺序排：

```text
1. 找可工作的参考脚本
2. 抄它的端口、波特率、协议
3. 串口调试助手做最小验证
4. EEG 软件确认 marker 出现
5. 再改 Python
6. 再跑具体 Session
```

这样能避免把时间浪费在错误的参数假设上。
